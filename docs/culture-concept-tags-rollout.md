# 문화·예절 개념 태그 운영 전환 검토

## 현황 (2026-10-17)
- 운영 `public.exam_culture_items`에는 `topic`(text)이 있으나 `concept_tags` 컬럼은 없음. 확인은 읽기 전용으로 수행.
- `topic`은 기존 콘텐츠 분류 값이므로 덮어쓰거나 개념 중복 판정에 임의로 전용하지 않음.
- 출제기 `CultureItem.concept_tags?: string[] | null`은 이미 지원하지만 DB 조회/전달은 별도 구현 필요.
- 준4급 ID 13/22(상원), 22/46(추석), 14/41(효), 42/43(어른 존중)은 임시 ID 기반 판정이 적용됨.

## 승인 전 작업
1. `supabase/migrations/20261017_exam_culture_concept_tags.sql`의 nullable 컬럼 추가를 검토한다. **현재 운영 DB에는 실행하지 않는다.**
2. 출제 데이터 조회 경로를 확인하여 컬럼이 존재할 때만 `concept_tags`를 전달하는 호환성 처리를 구현한다. 컬럼이 없으면 기존 조회를 유지한다.
3. 편집자가 확인한 문항에만 개념 태그를 입력한다. 문항 22처럼 여러 개념을 다루는 경우 `['sangwon','chuseok']`를 사용한다.
4. 신규 문항, 다른 급수, 누락 태그, 기존 준4급 fallback, 개념 태그 충돌, 문항 부족을 테스트한다.
5. 백업·롤백 절차와 운영 검증 결과를 확인한 뒤에만 운영 DB 변경을 별도 승인받는다.

## 롤백
- 출제기에서 태그 사용을 비활성화하면 nullable 컬럼이 남아 있어도 기존 동작을 유지한다.
- 컬럼 삭제는 데이터 손실을 일으킬 수 있으므로 자동 롤백 SQL에 포함하지 않는다.

## 주의
- 태그가 지정된 문항에 빈 배열 `[]`을 주면 명시적으로 '개념 제한 없음'으로 처리된다. `NULL`은 준4급 기존 ID fallback을 유지한다.
- 현재 태그는 단일 시험 안의 개념 중복을 막는다. **서로 다른 시험 간 동일 개념까지 배제하는 것은 별도 설계 대상**이다.
